# 第二篇文章与多金标准接入设计

## 目标

基于个人网站制作过程中的真实记录，重写四个 AI 工具对比文章，并把人工编辑后的转换方式作为第二组金标准，供后续 DeepSeek 写作参考。

## 文章设计

文章不进行模型能力排名，而是按照工作流阶段组织四个案例：Gemini 负责把视觉参考转成初始方向，Codex/ChatGPT 执行明确修改，Claude 调整项目信息的说服顺序，DeepSeek 提供更克制的中文表达参照。核心判断是：真实项目的效率来自识别当前需要减少的不确定性，并为任务携带完整上下文和验收标准。

所有第一人称经历只来自用户记录；对模型能力的描述限定在本次项目体验中。官方页面只用于确认产品背景，不用于证明主观对比结论。

## 金标准设计

每组范例由同名前缀的 `.input.json` 和 `.output.json` 构成。输入区分个人体验、公开事实、待验证问题和编辑推断；输出严格符合 `ArticleContent`。第二组范例重点示范：

- 多产品文章如何保持单一主线；
- 如何避免把一次体验外推成通用排名；
- 如何用具体前后差异支撑个人判断；
- 如何把角色分工进一步提炼为可迁移方法。

## 加载机制

`EditorialContext` 扫描 `examples/gold/*.input.json`，按文件名排序并加载对应 `.output.json`。Insight 获得每组范例中与分析相关的字段，Editor 获得完整输入与输出。保留首个范例属性作为兼容接口。

## 验证

- 两组输出均通过 `ArticleContent` 校验；
- Markdown 草稿包含七个规定板块且保持 `draft`；
- 分析和编辑提示词都包含第二个范例；
- 完整单元测试无回归。
