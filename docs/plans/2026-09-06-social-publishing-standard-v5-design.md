# 社媒发布标准 v5：实现设计

## 目标

让每篇产品洞察在人工审核前，同时获得结构稳定、可验证、可直接预览的 X 与小红书草稿；任何流程都不自动发布。

## 数据与校验

- `social_standard=v5` 标记采用新规范的产物，并保留旧 JSON 的读取兼容。
- X 支持 `thread` 与 `single` 两种形态，默认 `thread`。Thread 为 3–8 条，首条必须使用 16:9 总结卡片；程序添加 `n/N` 后做 280 字符保守预检。
- 官方账号使用结构化字段保存产品名、Handle、X 主页和核验状态。Handle 必须出现在正文中，主页路径必须与 Handle 一致。找不到账号时写入待人工补充清单，不允许编造。
- 小红书主线固定为深度洞察，标题最多 20 个字符，正文建议 300–500 字，最后一个正文段落必须是闭合式选择题或观点提问。

## 视觉输出

- X 为 16:9，总结页固定白底、深蓝标题、淡蓝模块。
- 小红书通常为 6–8 张 3:4 卡片，必要时使用深色收尾页。
- 对比与矩阵只使用圆角卡片，不生成 HTML 表格。
- 每次生成同时输出 `social-cards.html` 与 `social-cards.css`，供浏览器直接预览和人工修改；PNG 渲染流程继续保留。

## 审核边界

- PR 明确列出官方账号核验项、未找到的账号、截图与 Alt text。
- 所有社媒内容只作为草稿；合并 PR 不触发 X 或小红书发布。
