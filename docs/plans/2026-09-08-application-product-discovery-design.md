# 应用层 AI 产品选题与社媒完整性设计

## 目标

定时发现只把有明确用户、使用场景和可体验界面的 AI 应用作为文章主角。教育、医疗、法律、营销、电商、AIGC、办公协作、设计开发、消费产品、机器人和 B 端行业应用均可入选；模型、API、SDK、CLI、框架、底层基础设施、数据集、评测和只有代码仓库的技术项目不进入自动选题主线。

## 选题流程

1. 发现层继续从现有公开来源收集候选。
2. 程序先排除名称或摘要中明确属于终端工具、开发框架、SDK、数据库或模型基础设施的候选。手动指定产品跳过这层限制。
3. Scout 对剩余候选标记 `application_fit` 和 `application_category`，只有符合应用层定义且综合分达标的候选才能进入研究。
4. 技术项目仍可作为文章证据或竞品背景，但不能成为定时任务的主产品。

## 社媒完整性

DeepSeek 返回的 X Thread 超出 280 字符预算时，先保留完整句子，再按词边界压缩，确保编号加入后仍通过预检。小红书标题和正文结尾也做最小兼容处理。若社媒最终仍未生成，命令返回失败，不再让 GitHub 显示“文章成功、社媒缺失”的假成功。

## PR 完整性

创建草稿分支时记录本轮真正新增或修改的 `pr-body.md`。后续只使用该路径创建 PR；如果本轮没有社媒审核说明，则使用明确的失败提示，不再读取仓库中其他文章的旧说明。

## 验证

- 单元测试覆盖 TERMy 等技术候选被挡住、应用产品被保留和手动候选绕过规则。
- 单元测试覆盖 X Thread 超长自动压缩且仍符合 280 字符预算。
- 完整测试套件通过后，再推送代码、合并到 `main` 并手动触发一次线上自动发现。
